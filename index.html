Siteforge tries a direct browser request first. If a site's server blocks that (no CORS headers), it retries just that one file through a public read-only proxy (allorigins.win), which fetches it server-side and hands it back — that covers most publicly accessible sites. It still can't reach anything that's login-gated, behind a paywall or bot-check, or rendered client-side by JavaScript the proxy doesn't execute. Fetched stylesheets and scripts are inlined directly into the exported index.html rather than saved as separate .js/.css files — that keeps things to a single working file and avoids antivirus tools flagging a standalone script. For sites built with React/Vite/Webpack-style code splitting, the main bundle is also scanned for references to other chunk files it loads at runtime; this catches many but not all bundler setups. If a page can't be reached at all, or has nothing to extract, Siteforge stops and tells you rather than producing a blank download. Image format conversion happens locally using the canvas API — SVG and GIF files are kept as-is rather than converted. Every fetch attempt is reported in the log below. What happens when you press extract

The same pipeline runs no matter which input you use — only the first step changes.

01

Bring in the markup

Fetched from a live URL, pasted directly, or read from a file on your device.

02

Map the references

Stylesheet links, script tags, and image sources — including srcset, lazy-load attributes and inline base64 — are located and resolved to full URLs.

03

Fetch what's reachable

Every CORS-permitted stylesheet and script is inlined straight into index.html — no loose .js/.css files for anything to quarantine — and the main bundle is scanned for sibling chunk files it references, since React/Vite/Webpack builds often split code across several files.

04

Package it up

Download the images on their own, the self-contained HTML on its own, or one combined project folder.

Good to know

This runs entirely client-side — there's no server involved, and nothing you enter leaves your browser except the requests it makes to fetch the files you asked for, plus a request to allorigins.win when a file needs the fallback proxy. Windows or your antivirus may flag a downloaded `.js` file with a reputation warning (e.g. SmartScreen) simply because it's an unsigned file freshly built in a browser-generated ZIP, not from a known publisher — that's a false positive common to any browser-side ZIP containing scripts, not a sign the file is unsafe; choosing "run anyway" or unblocking it in file properties resolves it. The inspector-blocking on this page is a UI deterrent, not a security boundary — it's trivially bypassed by disabling JavaScript, using browser devtools' own protections, or viewing source another way, so don't rely on it to hide anything sensitive. Respect the terms of any site you extract from; this tool is meant for your own projects, backups, and learning from publicly available front-end code, not for republishing someone else's work as your own.
